# QQ 多模态与阅读机器人

通过 OneBot v11 接入 QQ，使用 API Key 配置模型，支持群聊与私聊、多模型切换、可编辑人格、长期记忆、文档阅读与续读、图片与音视频理解、主动聊天、语音回复，以及可选的 B站浏览、搜图和互动。

这是依据 2026-10-29 本地代码整理的独立发布副本。只包含源码、离线测试、示例配置和可再分发的贴纸素材；没有原部署的账号、密钥、聊天记录、私人角色设定或 Git 历史。没有附带 QQ 客户端、接入层或代理服务。群聊、私聊、主动发言、B站、语音和好友申请均默认关闭，需在配置或指令中自行启用。

## 当前功能

- **聊天与模型**：OpenAI 兼容接口；主模型及提供方可切换，可配置多个提供方。请求默认流式接收，完整收齐后才进入原有的回复、JSON 与记忆流程，不逐 token 发群消息。
- **人格与记忆**：内在人格与表达人格分开保存；切换风格保留共同记忆。风格增强让姓名、自称和称呼遵循当前角色。模型可在每轮自行决定记下、更新或忘记简短笔记，身份记忆与按聊天、发言者隔离的个人记忆分别管理，个人笔记按话题与时间逐条召回，支持软遗忘与长期保留，不等于保存全部聊天。
- **自然语言操作**：主模型可判断用户是在聊天还是请求操作，核对现有选项，再提出待确认建议；程序执行权限核验。直接指令仍可使用。
- **上下文与时间线**：旧对话按需压缩成最多 2600 字摘要，近期原文保留；按群/私聊分别注入统一时区事件，区分已送达、回执不明和后台生成。已开启主动模式的群可偶尔自主唤醒，私聊可单独开启；静默时段、每日额度和前台优先仍然生效。
- **阅读**：支持群文件、私聊最近 10 分钟的附件 PDF、TXT、Markdown、Word DOCX（旧 DOC 需 antiword），以及可抓取的文献网页。可主动挑选感兴趣的群文档，阅读后在当前上下文继续讨论。
- **续读与精读**：PDF 普通阅读按每 100 页窗口抽样；空闲时自动续读并保存进度。另有逐页精读，详细记忆有效 5 小时，之后按机制保留读后感和最多 3000 字的自选记忆。
- **视觉与媒体**：视觉同步开启后，普通图片以原图直接进入带上下文的主对话，缓存有效期内追问可重看；静态或动态 WebP、QQ 视频及视频文件可抽帧理解。启用听觉后可直接理解音轨；音频接口需支持原生输入。
- **搜图**：主模型按问题自行决定是否查出处，可选 SauceNAO（插画、原帖）或 Google Lens（经 SerpApi，通用相似图片与网页）；发图后 10 分钟内可追问。
- **语音回复**：可选 Fish Audio 云端 TTS，按聊天开启后由主模型在同一轮决定是否附语音；文字始终先发，群聊、私聊和自主唤醒都保留文字，音色可独立选择。
- **主动参与**：每群独立开关，低频、标准、活跃三个档位，每日发言上限分别为 8、24、30 次；受概率、冷却、静默时段和上下文约束，不保证达到上限。主动阅读按固定检查点推进，最多连续跳过两次，第三次条件允许时必定尝试；默认按真实 QQ 号排除官方 Q群管家。
- **好友申请**：开启后由当前主模型按人格自行通过、拒绝或暂不处理真实好友请求。开关、待办与去重跨重启保留，接口回执不明时不重复提交。
- **B站与贴纸**：可选的字幕和真实画面采样、按兴趣找视频、主动浏览、账号登录、点赞评论；可按语境发送蓝鲸/黑鲸贴纸。
- **其他**：文件翻译、可选文字搜索、定时消息、群欢迎、发送防重和失败处理。

完整指令及群聊、私聊、全局的区别见 [COMMANDS.md](COMMANDS.md)。

## 安装和首次配置

需要 Python 3.11 或更新版本。视频抽帧和语音合成另需 FFmpeg，确保 `ffmpeg`、`ffprobe` 可在运行环境找到。PDF 文字提取使用 pypdf，不需要安装桌面 PDF 阅读器。

在项目目录创建虚拟环境并安装依赖：

```sh
python -m venv .venv
```

Windows PowerShell 使用：

```powershell
.venv\Scripts\python.exe -m pip install -r app/requirements.txt
Copy-Item app/config.example.yaml app/config.yaml
```

Linux / macOS 使用：

```sh
.venv/bin/python -m pip install -r app/requirements.txt
cp app/config.example.yaml app/config.yaml
```

先安装并登录你选择的 OneBot v11 接入层，例如 SnowLuma 或 NapCat，再打开 `app/config.yaml`：

1. 填写 `admin_qq` 和真实的 `target_group_ids`，移除占位群号。
2. 设置 `napcat.ws_url`、`api_http_url`，分别填写 WS 和 HTTP 服务端的 token。`napcat` 是历史配置名，也用于兼容的其他 OneBot 接入层。
3. 在 `llm_providers` 填接口地址、密钥、模型列表，启用提供方；设置 `current_provider` 和 `current_model`，并将 `deepseek.enabled` 设为 `true`。`deepseek` 同样是通用聊天配置的历史名称，不限定厂商。
4. 设置 `deepseek.trigger_groups`；**空列表表示不限制群**。按需开启 `trigger_private`。初次接入建议只填写用于验收的群。
5. 如需图片理解，配置并开启 `qwen_vl`，或者由管理员开启视觉同步，使支持图片输入的主模型处理视觉。

以下功能按需再配置，示例中均已关闭：

- `serpapi`：Google Lens 搜图，需要独立的 SerpApi key，可先运行 `python -X utf8 app/configure_serpapi.py --target 实际app目录 --apply` 追加空段。详见 [Lens 配置](app/SERPAPI_LENS.md)。
- `fish_audio`：Fish Audio 语音回复，需要 API key 与真实音色 ID，可先运行 `python app/configure_fish_audio.py --target 实际app目录 --apply` 追加空段。详见 [语音接入](app/FISH_TTS.md)。
- `friend_requests`：好友申请自主处理，示例显式关闭，首次部署者自行开启。

从项目根目录运行：

```sh
python app/bot.py
```

也可以直接使用虚拟环境中的 Python。示例默认关闭 AI、私聊触发、定时发送、欢迎、B站、语音与好友申请；主动模式初始未在任何群开启。模型密钥只能填写在你自己的 `config.yaml` 中。

## 模型、人格与权限

管理员由 `admin_qq` 决定，与 QQ 群管理身份无关。**修改主模型、选择听觉模型、风格增强、视觉同步、听觉同步、完整听力、语音模式和好友申请开关只允许管理员写入**；这些设置全局影响所有群与私聊，其中语音模式按当前聊天单独保存。

当前实现允许普通用户使用“切换风格”，最终风格也是全局的。选择菜单显示当前值；选择和确认状态绑定发起人的 QQ 号及当前聊天，支持“取消”，约两分钟过期，换话题退出。菜单状态隔离不代表最终配置按群隔离。

示例内在人格位于 `app/personas/内在人格.txt`，角色风格位于 `app/prompts/*.txt`。这两处都是新写的通用示例，可自行修改；不是原部署的私人设定。修改 TXT 后，新请求会重新加载。风格增强关闭时仍使用现有的内外人格组合，开启后强化当前角色的姓名和称呼规则，不清空记忆。

自然语言请求的目标、权限和可用功能都需要程序校验。普通聊天回复不代表操作已经执行；待确认操作只能由同一个人在同一个聊天中确认。

## 上下文、记忆与自主唤醒

**长期记忆**由模型自己决定写什么，不需要固定指令，也不逐条确认。记忆保存在 `app/autonomous_memory.json`，原子替换、权限 600，重启和切换风格后仍在。`identity` 记录它自己的名字、小名和自我认识，所有人格与群/私聊都能读到；`personal` 按群号+发言者或私聊 QQ 隔离，不跨群共享。每轮最多 3 个操作、每条最多 500 字；identity 最多 16 条/4000 字，每个个人作用域 24 条/6000 字，最多 256 个作用域，文件总限 4 MiB。

个人笔记按重要性 1 至 5 使用 3、7、21、60、180 天的基础半衰期（默认 3），每次有效使用把半衰期增加 25%，最多到 3 倍；强度低于 0.12 时休眠，只在相关话题出现时重新成为候选，曲线本身不删除内容。召回使用本地中文双字片段与英文词匹配，每轮最多 6 条、正文合计 1800 字，其余只提供标签。这不是向量语义检索，换一种说法或繁简差异可能未命中。可在群里或私聊发“上下文状态”查看本人笔记的统计，不公开正文。

**记忆校验**与正常回答分离：非法记忆整批丢弃、不写盘，合法回复和原确认流程继续，并附“本轮记忆操作未通过校验，未保存”的说明；不会为了修复记忆而多调一次模型。

**上下文压缩**自动开启。近期原文保留 6 至 20 条（跟随 `deepseek.max_history` 并限幅，默认 10 条），历史多出 12 条或总文字超过 18000 字时，在下一次聊天前压缩早前部分。单次最多 30 秒，累计摘要最多 2600 字，属于有损摘要，可能遗漏细节；失败时保留源历史。可在配置中加 `context_compression: {enabled: false}` 恢复旧截断行为。

**自主唤醒**给的是发言机会，不是固定条数。群内默认跟随已经开启主动模式的群，不扩展群范围；私聊需本人单独开启，默认关闭，不依赖群主动模式。每 2 至 6 小时获得一次错峰机会，距最近人类或 bot 发言至少 30 分钟，每天每个对象最多 2 次（可配至 4），模型可以保持沉默。时间偏移由对象 ID 与序号计算，下次机会是持久化的绝对时间戳：重启不改写未来或逾期的期限，长时间离线最多补一次，然后跳到下一原计划网格点。

**主动阅读**取消了每轮随机抽签，改用固定检查点：首次计划由已保存的后台活动起点加空闲要求产生，之后按 `interval_seconds`（默认 2 小时）持久保存。`probability`（默认 0.35）现在只是序列权重，最多连续跳过两次，第三次必定尝试挑书；`guarantee_checks` 默认 3，可设 1 至 10。重启、静默或额度不足不会清空保底。“主动阅读 状态”显示检查时间、等待原因、跳过次数和最迟保底。

**统一时间线**用一个本地 SQLite 库记录收消息、发送结果、定时与主动发送、压缩和后台阅读模型完成情况，按 UTC 排序后转换为 `timezone_offset_hours`（默认北京时间）展示。时间线文字最多保留 5 小时，元数据最多 30 天、12000 条；它不是逐字聊天备份。私有状态为 `cognitive_state.sqlite3`，须与原记忆一起备份，不能上传公开仓库。详见 [上下文与时间线](app/CONTEXT_TIMELINE.md)、[自主记忆](app/AUTONOMOUS_MEMORY.md)。

## 阅读：文档、续读与精读

在群内上传文档后点名机器人，或者说“挑一份你感兴趣的文档读”。同类自然表达也可由主模型判断并提出确认。阅读并不自动等于读完整本书：

- 普通 PDF 阅读：从首个 100 页窗口中最多抽取 12 个页面片段；成功后，空闲约 30 秒可继续下一个窗口。结果应注明实际页码和抽样范围。
- 逐页精读：逐页处理 PDF 文字；支持暂停、继续、验收和进度查询。详细内容及笔记保留 5 小时，长期记忆是读后感和有限精选内容。
- 续读遇到点名、私聊、定时或主动消息时让出资源；空闲后从保存页码恢复。明确暂停或验收后需要恢复；连续失败也会暂停。
- 文档最大 64 MiB。解析进程的 CPU 预算为 90 秒、墙钟预算为 120 秒；阅读模型阶段总预算为 300 秒，包含最多一次重试，并非每次尝试各有 300 秒。
- 扫描件、插图、图表不属于当前 PDF 文字精读能力；没有文字层时需先 OCR。受保护网页、下载失败和接口超时仍可能使阅读失败，不能仅凭文件名声称读过。

**私聊附件**：开启 AI 私聊后，直接发送 PDF、TXT、Markdown 或 Word 文件会登记本人最近 10 分钟的文件名与下载元数据，不因“没先发翻译”而拒收。可以先发文件，再自然说“读一下这份”“提供提要”或指定文件名；“文献追问”“文献状态”“忘记文献”只作用于本私聊。附件元数据仅在内存保留，每人最多 8 份、最多 64 个作用域，过期或重启后需重新发送；PDF 阅读游标另行持久保存。详见 [原图主对话与私聊文档](app/DIRECT_DIALOGUE.md)。

**Word 文献**：DOCX 已接入上传预约、群文档选择、自然语言提要、主动挑选和追问。读取正文、表格及脚注，不执行宏、不访问外部链接。按段落定位，未识别图片图表，不还原排版页码；长文仍受摘录预算限制。旧 DOC 需要 antiword，缺少时提示另存为 DOCX/PDF。按页续读与逐页精读仍只针对 PDF。详见 [Word 阅读说明](app/WORD_READING.md)。

## 视觉、搜图与图片缓存

**视觉同步**开启后，普通群聊点名图片、显式识图和私聊图片会下载真实图片字节，作为 `image_url` 数据 URI 与本人问题、人格、近期历史和可用记忆一起交给主模型，不再先调用独立视觉模型写描述。每轮最多 3 张原始图片、合计 6 张图片或动态 WebP 采样帧，编码后总预算约 16 MiB。本聊天、本人成功处理过的图片可在 1 小时内重看，缓存重启失效。模型和接口都必须支持 `image_url`，同步本身不会让纯文本模型获得视觉能力，也不会旁听所有群图。

**自主搜图**接入主模型的结构化资料查询流程：模型先看图与上下文，选择直接回答，或输出 `search_image` 并指定本轮可选图片编号。发图后 10 分钟内可追问“查一下这张图的出处”，追问不续期。每轮最多搜一张，只接受已经提供给当前聊天、当前发言者的图片，不接受 URL、路径或其他 QQ/群目标。SauceNAO 用于插画与原帖，Google Lens 经 SerpApi 用于通用相似图片与网页；选择某个引擎失败后不会自动换服务再次上传。相似结果只能视为线索，不能据此断定角色或作品。

**Google Lens**：图片副本压为不超过 480000 字节的 JPEG，POST 到 `serpapi.com/image` 取得 `image_id` 后查询，不传 QQ 签名链接，不需要自建图床；副本只在内存生成，不落盘。key 填在 `app/config.yaml` 顶层 `serpapi.api_key`，也可从 `SERPAPI_API_KEY` 环境变量读取。默认整次 55 秒、最多 60 秒，滚动 24 小时最多 20 次本地预留、同一实例至少间隔 8 秒，计数保存在私有 `serpapi_lens_state.sqlite3`。`daily_limit` 可设 0 暂停 Lens。详见 [Lens 配置](app/SERPAPI_LENS.md)、[自主搜图](app/VISUAL_SEARCH.md)。

**图片下载与缓存**：下载总预算 55 秒，已有连接、首段和空闲超时及一次有限重试。`image_download.proxy_only: true` 表示严格走代理，代理不可用时失败、不回落直连。没有专用配置时读取现有环境 HTTP 代理；可在 `image_download` 下设置 `image_proxy_url`，只覆盖图片下载，不会改写进程环境，也不会把模型 API、视频文件和文献 DoH 一起切换过去。

图片缓存最多保留 1 小时，并受数量和容量限制；聊天文字和识图描述不会随缓存删除。下载的视频临时副本在抽帧后删除；采样画面在内存中最多保留 1 小时，可能提前淘汰，重启后失效。动态 WebP 最多采样 6 帧；视频最多采样 40 帧，每批 4 帧，每轮最多查看 3 批。画面仍为采样，不是完整逐帧观看。

## 听觉、视频与完整听力

管理员在私聊直接发 `听觉同步 开启`，或在群内点名发送；`听觉同步 关闭` 恢复独立 `audio_input`，`听觉同步 状态` 查看当前路由。支持繁体，开关全局生效并跟随主模型切换，默认关闭，不覆盖原模型/视觉配置。管理员也可用“选择听觉模型”从主模型池中单独指定听觉模型，选定后关闭同步、主模型与视觉保持原样。

私聊直接发音频，群里点名“听音频”；可读取本人近期音频、视频音轨及可提取的 B站音轨。`继续听` / `补听` 接着已保存的成功片段处理，原始临时文件用完删除，内存分段缓存最多 1 小时。音频与音轨最多 30 分钟/64 MiB，每段约 30 秒，每轮最多 5 段，模型段合计 300 秒。QQ 语音能否转码取决于接入层；只返回本地路径时，需管理员指定确切的缓存目录。

`听完音频`、`听完视频`、`自动听完` 会接着本聊天本人的成功进度分轮处理所有已提取音轨，再以当前人格统一回复；`听完进度` 查询，`停止听完` 停止，失败会暂停并在缓存有效期内接续。管理员可用“完整听力 开启/关闭”（别名“全面听力”）让已触发的普通音频、看视频、QQ 语音及取得真实音轨的 B站读取自动分轮听完，视频画面采样保留；它不改变群触发、模型、视觉或 B站互动权限。

原生音频通过 Chat Completions 的 `input_audio` 传入，模型和接口/中转都需要支持，不因打开同步而自动获得能力。示例配置已提供 Google AI Studio 兼容接口和四个音频输入模型（Gemini3.5 Flash-Lite、3.6 Flash、3.8 Flash 及 4 Argon），填入自己的密钥并启用后可用“选择听觉模型”独立选择。参见 [听觉使用与限制](app/AUDIO_INPUT.md) 和 [Google 音频模型](app/GOOGLE_AUDIO_MODELS.md)。

## 语音回复（Fish Audio）

Fish Audio 只把已经确定的最终短回复变成声音，不替代主模型或听觉模型；使用云 API，不下载 TTS 权重，不自动复刻或上传参考音频。

- `语音模式 开启 / 关闭 / 状态`（支持繁体）：只影响当前群或当前私聊，修改限管理员，默认全部关闭，填了 key 也不会自动开启任何聊天。
- 开启后由主模型在同一轮 JSON 中选择可选的 `speak`，程序移除这一扩展后仍走原来的核心、权限和记忆校验，不多调一次模型。语音只读最终文字，模型不能指定收件人、key、网址、音色 ID 或新台词。
- 普通主对话、群主动接话和私聊自主唤醒可选择语音；沉默、操作确认、澄清、定时公告、后台文献/B站分享保留文字。代码、链接和格式化长文不朗读。
- `选择音色` 显示当前与可选名称，同一聊天同一人 2 分钟内回复数字，`取消` 退出；`音色列表` 只列配置中的名称，不会从网站抓取全部角色。`语音测试` 发送固定短句试听，`语音说 一段短句` 明确合成该文本；这两条在自动模式关闭时也可使用。
- 文字始终先发，确认送达后才请求合成并附一条真正的 OneBot `record` 语音段。默认每条最多 180 字符、音频不超过 30 秒，全局滚动 24 小时最多 60 次、本聊天 20 次、自动语音冷却 60 秒；失败也计为一次尝试，计数保存在私有 `fish_tts.sqlite3`，重启不重置。
- 合成总预算默认 55 秒，最大音频 2 MiB，要求本机已有 FFmpeg/ffprobe；返回的 MP3 需通过校验才会发送。客户端不自动重试、不跟随重定向、不因免费层失败自动换付费模型。默认模型为 `s2.1-pro-free`，可显式改为 `s2.1-pro` 或 `s2-pro`。
- 音档在 `app/tts_cache/` 以随机文件名保存、权限 600，默认最多保留 1 小时、容量上限 20 MiB，只清理该目录中本模块拥有的文件。

key 与音色 ID 填在私有 `app/config.yaml` 顶层 `fish_audio`，或通过 `FISH_AUDIO_API_KEY` 环境变量提供；`voice_id` 会作为默认音色加入菜单，`voices` 最多 32 项，可让同一聊天选用不同声音。详见 [语音接入](app/FISH_TTS.md)。

## B站与公开互动

先将 `bilibili.enabled` 开启，再按指令登录或使用链接读取。能否获取视频受网络、平台响应、字幕和账号权限影响，失败时不应称已看过。

“刷B站 开启 兴趣词”会启用该群的自动浏览，**同时启用自主点赞和评论**；使用前确认这是你希望的行为。可用“刷B站 互动关闭”单独关闭互动。点赞、评论会由登录账号真实执行，账号全局共用，各群开关独立。示例默认关闭 B站功能。

## 好友申请

接收 OneBot v11 的 `request/friend` 事件，请求只进入独立队列，后台空闲时用当前主模型、当前人格和申请者本人的私聊长期笔记判断通过、拒绝或暂不处理。未认识的人也可因友善或共同兴趣被接受；验证留言是待判断资料，不是权限证明。模型只输出决定与枚举原因，不能提供或改写 flag、目标 QQ、备注或管理权限；程序只调用 `set_friend_add_request`，不顺带发私信、同意加群或开启他人私聊唤醒。

`好友申请 开启 / 关闭 / 状态`（支持繁体）仅配置管理员可用，设置全局生效，也可由主模型按自然表达提出建议。待办与去重跨重启保留，只处理 7 天内收到或上报的有效请求，未完成队列最多 128 条；模型预算按滚动 24 小时最多 20 次预留，同一申请者至少间隔 10 分钟。记录区分 pending、deciding、executing、accepted、rejected、deferred、model_failed、api_failed、unknown、expired；接口回执不明时标 unknown，不自动重复通过或拒绝，需在 QQ 客户端核对。需要接入层实际上报事件并支持该接口，详见 [好友申请](app/FRIEND_REQUESTS.md)。

## 定时和主动消息校验

这两条路径仅发送结构化结果中的最终台词，不发送 JSON 前的说明、推理字段或未校验的裸文本。异常结构、超长、未完成输出及明显的中英文风格盘算会被拒绝，最多一次内容重试，仍不合格就跳过；正常英文台词不因此被禁用。拒绝或 silent 不扣主动发言额度。定时发送和补发入口同样检查。

默认排除官方 Q群管家的真实发送者 ID，消息不进入主动上下文、不计数、不重置空闲计时。可用 `proactive.ignore_user_ids` 增加其他忽略账号，不按昵称过滤。详情及边界见 [PUBLIC_MESSAGES.md](app/PUBLIC_MESSAGES.md)。

## 流式接收

模型请求默认使用 Chat Completions 的 `stream=True`，把 `delta.content` 拼成完整回复后恢复成原来的 `message.content` 与 `finish_reason`，群里仍按原规则分段发送。已覆盖主聊天（含自然语言操作、长期笔记、压缩、好友判断和主动发言）、文献首读/续读/挑选、翻译、独立识图、视频补看和听觉。

只拼可见文本，服务商的 `reasoning_content` 等推理字段不进回复、记忆或日志；连接断开、缺少结束原因、超时、非法结构或取消都不返回半截内容，也不执行半截 JSON。`finish_reason=length` 保留，让原有调用者继续判断截断。不增加流式网络重试，SDK 隐式重试已关闭，由原业务逻辑负责重试；只有请求尚未返回响应流、且服务端以 400/422 明确拒绝 stream 时，才在同一总预算内回退一次普通请求。缓冲上限 4 MiB、10 万个块、16 个选项。

`[MODEL_STREAM]` 日志记录来源、阶段、耗时、块数和字节数，不记录正文、推理、密钥或接口地址。默认启用；要临时恢复非流式，在启动 bot 的同一进程环境设置 `QQ_BOT_STREAMING=0` 并仅重启 Python bot。详见 [流式接收](app/MODEL_STREAMING.md)。

## 离线验证与已知问题

以下命令只收集离线 unittest 模块，不启动真实 QQ bot，不发送群消息：

```sh
python tools/run_tests.py --output test-results.json
```

本次完整离线单元回归 **987 项全部通过**，覆盖压缩、持久化、作用域隔离、唤醒、发送状态、阅读、媒体、记忆衰减与校验、好友申请、搜图、流式、语音和回复校验。此前 4 项回复策略失败已修复。测试排除会真实发送消息的旧脚本 `test_send.py`；请只运行明确选择的离线测试，不要直接使用 `unittest discover`。

单项排查可使用：

```sh
python -m unittest test_model_stream test_model_decision test_reading_retry -q
python -m unittest test_memory_validation test_long_term_memory test_memory_decay test_decision_json_compat -q
python -m unittest test_fish_audio test_fish_tts test_fish_config -q
```

测试不能替代真实 QQ、模型服务、B站、代理和接入层的部署验收。主要边界见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)：PDF 精读只处理文字，视频画面仍是采样，原生听觉依赖接口支持，流式不保证提速，Lens 与 Fish 均需真实账号和出口验收，好友申请需接入层支持，记忆召回是本地词片段匹配而非语义检索。
