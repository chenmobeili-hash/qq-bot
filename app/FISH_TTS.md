# Fish Audio：由模型自主选择的QQ语音

主模型仍负责聊天，人格与长期记忆不变；Fish Audio只把已经确定的最终短回复变成声音，不替代主模型或听觉模型。本模块使用云API，不下载TTS模型权重，不自动复刻/上传参考音频。

## 私有配置

先安装源码，再在实际app目录运行 `python configure_fish_audio.py --target /实际路径/app` 预览；加 `--apply` 只会追加key留空的fish_audio段，原配置逐字备份，已有段不覆盖。不要把key贴到群里、聊天、日志或公开仓库。

在实际 `app/config.yaml` 顶层找到 `fish_audio`，填写：

```yaml
fish_audio:
  enabled: true
  api_key: "在私有文件中填你的Fish Audio API key"
  model: s2.1-pro-free
  voice_id: "在Fish Audio选定音色的模型ID/reference_id"
```

也可通过bot进程的 `FISH_AUDIO_API_KEY` 环境变量给key。音色ID不是API key，也不是主模型名；仅有key无法决定角色声音。从Fish Audio音色页面取得对应模型ID，或使用自己已建立的声音ID。不会通过一个角色名称自动推导出真实音色。

多音色可在同一段中使用：

```yaml
  voices:
    角色A: "替换为实际音色ID"
    轻声: "替换为另一实际音色ID"
  default_voice: 角色A
```

`voice_id`会作为“默认音色”加入菜单。`voices`最多32项，显示名称不含网址/路径；同一聊天可选不同声音。不要再建立第二个fish_audio YAML段。

默认严格指定 `s2.1-pro-free`，可显式改 `s2.1-pro` 或 `s2-pro`。拼错模型会在本地拒绝，不省略model请求头，不因免费层失败自动换付费模型。实际账号是否可用、限速和用量，以Fish官方及账号为准。

## 群聊和私聊

- `语音模式 开启 / 关闭 / 状态`（也支持繁体）：**只影响当前群或当前私聊**。群、私聊的开关修改均仅配置管理员；状态可查询。默认全部关闭，填key不会自动开启任何聊天。
- 开启后，由主模型在同一轮完整JSON中选择可选`speak`布尔值。程序移除这一扩展后，仍交原来的核心/权限/记忆校验，不多调一次模型。语音只读最终文字，不允许模型指定收件人、key、网址、音色ID或新台词。
- 普通主对话（含图片/媒体进入主对话后的回复）、群主动接话、私聊自主唤醒可选择语音；沉默、操作确认、澄清、定时公告、后台文献/B站分享保留文字。代码、链接、格式化长文不朗读。
- `选择音色`：管理员打开当前聊天的音色菜单，显示当前与可选名称；同一聊天同一人回复数字，2分钟内有效，`取消`退出。不同群或私聊互不抢占，打开模型/风格菜单会替换当前选择；设置或权限变化时旧菜单失效。不会公开key或完整音色ID。
- `音色列表`：看配置中可选名称，不会自动从网站抓取或下载所有角色模型。
- `语音测试`：发送固定短句试听；`语音说 你好，今天也辛苦了。`：明确合成这句文本。群里需@bot，私聊直接发。这些显式请求在自动模式关闭时也可使用，仍受额度限制。
- 自然说“开启这个群的语音”“换成轻声”“用语音说一句……”时，主模型可以提出对应操作，仍走原来的同人、同聊天、送达后确认流程；没有确认不修改开关。

文字始终先发，确认送达后才请求Fish并附一条真正的OneBot `record`语音段；不把API生成的MP3当普通附件替代成功。主要私聊分块发送和媒体私聊发送两个路径都已接入。音色选择不自动跟随风格切换；切换人格、音色、key或本聊天有新点名/私聊消息时，旧语音结果会被丢弃。

## 限制、费用和失败

默认每条最多180字符、实际音频不超过30秒，不静默截断长文。模型建议短句最多120字。不合适时只发文字。默认全局滚动24小时最多60次、本聊天20次、自动语音冷却60秒；显式请求绕过自动冷却，但不绕过次数限制。失败也计为一次尝试，计数保存至私有`fish_tts.sqlite3*`，重启不重置。

合成总预算默认55秒；最大音频2MiB；要求本机已有FFmpeg/ffprobe（视频/音频功能通常已安装）。在请求前检查解码器存在；返回完整音频后，ffprobe确认MP3可解析、有音轨且时长符合才发送。客户端不自动重试、不跟随重定向、不换提供方或付费模型。401/402/403/429/503、超时、坏音频分开记录安全原因码，不记录key、代理地址、台词或服务商原文。

若失败，文字照常保留；自动语音不反复向群报错，显式试听/朗读会给一次失败提示。发送回执未知时不自动重发，避免重复语音。关闭模式会阻止后续自动调用，在途请求可能已产生用量；删除本地音档不代表删除Fish服务器侧数据。

使用环境HTTP(S)代理（默认）或独立`fish_audio.proxy`，不修改全局代理或其他下载器。证书校验保持开启；代理故障不自动改路绕行。跨进程平台凭证仍由部署环境原有的启动方式管理，不写死。

## 缓存与隐私

合成音档在`app/tts_cache/`随机文件名、权限600，默认最多保留1小时，容量上限20MiB，运行中每分钟清理，重启后也清理过期文件。只删该目录中本模块拥有的文件，不删上传文件、聊天文字、识别结果或长期记忆。正在发送的文件会暂时保护，结束后再正常过期。bot停止时无法执行清理，恢复后补清。

语音用Base64内联交OneBot，避免QQ与bot路径不共享、外部临时链接以及新的CDN下载步骤；时间线只记语音标记与已发送文字，不把音频或其Base64作为持久上下文。最终能否发成QQ语音仍需实际SnowLuma验证；接口返回音频不等于QQ已收到。

## 离线与实机验收

本地：`python -m unittest test_fish_audio test_fish_tts test_fish_config -q`。使用假key和本地假HTTP服务，包含真实MP3/ffprobe解码以及群聊、私聊、权限、取消、额度、记忆修复兼容测试。不要运行`test_send.py`或无筛选的unittest discover。

实际部署：空闲时仅重启Python bot，保留原QQ/SnowLuma及守护恢复流程。先填key和真实音色ID，管理员私聊发`语音测试`，确认文字→`phase=request_start/headers/first_body/audio_received/audio_validated`→`status=sent`→QQ可播放。再在目标群@bot测试，最后分别开启语音模式，检查主模型只在合适时选择附语音。不要用一行connected或已配置宣称全部验收通过。

官方依据：[TTS API](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech)、[能力及免费层说明](https://docs.fish.audio/overview/capabilities)。本地没有用户实际key，未进行真实Fish账户、真实QQ或部署验收。
