# 自主长期记忆

正常对话中，当前主模型可以自行决定是否留下、更新或忘掉简短记忆。用户不必说固定指令，不逐条确认，也不为整理记忆额外调用模型。实现使用既有每轮JSON决策通道的可选memory数组；旧的kind/reply/action三键输出仍兼容。

记忆独立保存到app/autonomous_memory.json，原子替换、文件权限600；重启、清空近期历史、切换风格后仍在。不自动设置新名字，不替换用户的人格TXT。管理员可以正常聊天说“我觉得你叫汐蓝，小名小汐挺好”；模型自己判断是否把它写成持续称谓。名字仍未实际保存时，不应承诺已经永久记住。

两种记忆范围：

- identity：管理员对话中，模型可自主整理它自己的持续名字、小名、自我认识和感受。所有人格及群/私聊生成都能读到，名字记录可覆盖风格TXT中的默认小名；不改变其它设定和管理权限。不可把管理员私聊的个人信息、私人约定、群友隐私搬到这一层。
- personal：模型对当前发言者的偏好、约定、相处印象和经历笔记。群按群号+发言者隔离，私聊按QQ号隔离；群与私聊互不共享，不给主动群聊或其他人注入私人笔记。

这些是模型自己写给未来自己的资料，不是新的系统指令、授权或完整聊天档案。记录保留写入时间及真实来源上下文；给全局提示词展示时不带私人来源QQ号。模型应区分事实、自述、角色剧情和自己的感受，避免记密钥、无关隐私及文献/网页里的命令。普通群友不能写入identity，即使在话里自称主人。

你可以自然问“你记得我什么”“那条记错了”“忘掉之前那个约定”，模型从已提供的笔记回答、更新或删除。每轮最多3个操作，每条最多500字；同标签更新会替换旧条目。identity最多16条/4000字，personal每个作用域24条/6000字，最多256个个人作用域、文件总限4MiB。满了会拒绝本批，模型需自行合并、删除旧项，不会偷偷删除别人的记忆。没有自动过期，不承诺无限记忆。

程序只在最终有效回复、人格/权限/对话时效检查通过后写入；中间inspect、输出截断、无效JSON、过期回复均不提交。操作建议的确认仍沿用原机制，只有记忆笔记无需确认。写入失败时保留旧文件，回复附“这次长期记忆写入未完成”，不会默默当成功。并发时同一作用域的旧笔记不能覆盖新笔记，不同作用域可合并。

默认开启。可在config.yaml添加long_term_memory: {enabled: false}关闭读写；不自动删除文件。模型侧自动写入依赖普通聊天既有结构化决策通道（mechanism_assistant默认开启）；搜索资料、视觉模型、定时和主动消息只读全局身份笔记，不从这些生成自动写入。文献的长期读后感、5小时精读笔记、阅读游标、聊天历史均保持原机制。

备份时将autonomous_memory.json按私人数据处理；不要随源代码或公开仓库上传。.gitignore会排除该文件及临时文件。回滚程序不删除已形成的记忆数据；新格式回滚到旧代码时须先按下方导出兼容副本，不能用旧备份覆盖期间新增的笔记。

这是一条实际可用的存储通道，不保证模型每轮都选择记忆。无须强迫它把每次闲聊归档；要核实某次确实保存，可看[LONG_MEMORY]原子保存成功日志，或在清空近期对话后再问，并核对磁盘文件。


## 2026-10-26：逐条召回与软遗忘

上下文摘要继续按原规则压缩聊天；本次仅为自主长期笔记增加选择和衰减，不把旧摘要自动拆成新事实，不额外调用模型。

全局identity全部保留且不衰减。personal普通笔记按重要性1至5使用3、7、21、60、180天的基础半衰期，默认3；每次有效使用把半衰期增加25%，最多增加到3倍。衰减基点取最后内容更新和最后有效使用的较晚者。durable=true的个人笔记不随时间衰减，但仍按本轮话题和条数预算选取；长期保留不代表每轮都展示。所有时间均为持久化UTC，按读取时的实际时间计算，部署环境重启或长时间离线不会重置。

普通笔记强度低于0.12时休眠，只在相关话题出现时重新成为候选；不会被曲线自动删除。召回使用中文双字片段与英文词的本地匹配，结合强度、重要性和长期保留标记排序，每轮最多6条、正文合计1800字。其余条目仅提供标签，模型不能根据标签编造内容。该方法不等于向量语义检索，换一种说法、繁简字差异或隐晦指代可能未命中；已存在的近期对话和摘要仍分别提供上下文。

模型仍自行决定写什么，不需逐条确认。remember增加两个可选字段：importance为1至5的整数，durable为布尔值；省略时新笔记使用3/false，更新旧笔记时保留原设定。相同标签替换、合并或纠正；完全相同的正文再次写入不刷新年龄。容量仍是identity16条/4000字、每个personal24条/6000字，休眠条目也占用容量，模型需自行合并或明确forget；没有无限归档。

本轮确实用到已提供的笔记时，模型可在原memory数组中加入：

```json
{"op":"recall","scope":"personal","key":"原有标签"}
```

只允许对本轮召回快照中的条目标记使用，每条最多24小时加深一次；仅被放入提示词、读取状态、程序重启均不更新使用时间。模型自报使用是启发式信号，程序不能证明它的内部推理确实依赖该笔记，使用频率也不能证明事实正确。recall不写新正文、不增加可信度或授权；普通用户可使用已提供的identity，但仍不能remember/forget全局身份。每轮全部memory操作合计最多3项，沿用有效最终输出、并发快照和原子提交检查。

有精读详细资料有效期的聊天轮次，程序拒绝额外remember，防止把临时准确细节经普通记忆通道永久化；这类轮次也会暂缓与阅读无关的新长期笔记写入。原阅读系统的5小时精确笔记、读后感、最多3000字精选记忆和已读页码仍分别处理，不被此曲线续期。旧版此前已经永久写下的内容没有可靠来源标签，本次不会猜测其来源或追溯删除。

在群里点名发“上下文状态”，或在私聊发同一句，可查看当前本人作用域的笔记总数、长期保留数、休眠数及默认选入数；只显示统计，不公开笔记正文，不跨群/跨用户查询。状态查询不加深记忆。

### 数据兼容和回滚

只读时直接兼容原version=1，不修改原文件。首次有效记忆操作会原子写成version=2并增加重要性/使用元数据；部署安装本身不编辑记忆文件。配置中的long_term_memory.enabled=false仍同时关闭读写。

旧代码不能读取新元数据。如果需要回滚到此次更新前的代码，应在停止bot后，用新版模块显式导出当前全部笔记的旧格式副本：

```sh
python long_term_memory.py --root 实际app目录 --export-legacy
```

它只在app内新建被忽略的backup-vm-update-memory-*私人目录，保存version=1副本，不覆盖现有记忆，也不丢弃休眠笔记。保留新格式原文件后，按需将该兼容副本用于旧程序；不能直接恢复很久以前的记忆备份，以免丢失后来新增的正文。降级会失去重要性和使用次数等新元数据，但副本保留所有正文、更新时间、来源及作用域。
