# 原生音频输入与听觉同步

## 使用

- 管理员：`听觉同步 开启`、`听觉同步 关闭`、`听觉同步 状态`，支持繁体 `聽覺同步`。
- 开关全局生效，群内需点名机器人，私聊直接发送。普通用户可查看状态；自然语言调整也走现有建议、确认和管理员核验。
- 开启后音频模型、接口和密钥跟随主模型。关闭后恢复菜单选定的独立听觉模型（未选时用 `audio_input`），不改原配置，不影响视觉同步。
- 私聊直接发 MP3、WAV、M4A、AAC、FLAC、Ogg/Opus、AMR 文件，或 QQ 语音。
- 群内先发音频/视频，再 `@bot 听音频`；也可先点名预约，再在10分钟内发送。只读取当前聊天中本人近期附件。
- `继续听`、`补听` 从当前聊天、本人的成功片段进度继续；群内需点名。`继续看视频` 仍可补看画面，并在听觉可用时继续处理音轨。

## 从主模型池选择听觉模型

管理员在群或私聊发送 `选择听觉模型`（繁体 `選擇聽覺模型`），先选提供方，再选模型。
菜单显示当前听觉模型，可随时回复 `取消`，两分钟有效；数字只在发起菜单的当前聊天、当前QQ号下有效。
提供方和模型沿用 `llm_providers` 主模型池，列表不是音频能力认证。
最终选定会全局启用独立听觉并关闭同步，**不修改主模型、视觉路由、config.yaml或人格**。
开启同步后临时跟随主模型；再次关闭则恢复菜单选项。
`hearing_sync_state.json` 原子保存同步开关与提供方/模型名字，不复制密钥；每次从现有池读取最新接口和密钥。
禁用或移除提供方/模型后听觉停止，不回落主模型或其他服务；接口尚未验证时不会声称已经能听。
原 `audio_input` 的群白名单、附近画面选项等设置继续保留。
自然表达“想单独换听声音的模型，聊天模型别动”会进入现有模型意图判断及确认流程。

## 配置与接口

默认不启用听觉同步，缺少 `audio_input` 时不新增音频调用。示例：

```yaml
audio_input:
  enabled: false
  endpoint: https://api.example.com/v1
  api_key: ""
  model: YOUR_AUDIO_MODEL
  api_format: input_audio
  trigger_groups: []
  include_frames: false
  local_record_roots: []
```

`trigger_groups` 留空表示不限制群；未设置此字段则沿用聊天群白名单。`include_frames` 仅当该音频接口同时支持图片输入时开启，每段附带最多2张附近采样画面。默认分别读取声音和画面，再交给主模型综合。

采用 Chat Completions 的 `input_audio` 消息部分，发送实际 MP3 字节并请求文字结果。模型自身和当前接口/中转都必须支持该格式；开启同步只检查路由已配置，不会暗中发送测试音频或保证兼容。拒绝、不支持、超时或回答格式无效时明确失败，不回落为“仅凭文件名猜测声音”。原生听觉不需要先接独立语音转写 API。

请求格式依据 [OpenAI 官方音频文档](https://developers.openai.com/api/docs/guides/audio-chat-completions)。此适配器不代表所有多模态厂商的原生接口都兼容，不会自动改写为厂商私有音频格式。Python SDK 依赖要求已提高为 `openai>=1.60.0`。

## QQ 语音与 B站

QQ 语音尝试通过接入层 `get_record` 请求转成 MP3，支持返回 URL 或 Base64。若接入层只返回本地路径，管理员需把**真实转码缓存目录**加入 `audio_input.local_record_roots`；不默认开放整个磁盘，也不打开消息任意指定的本地文件。SILK 仍无法解码、接口未实现或本机没有同一份文件时，会提示改发普通音频。

该接口的规范见 [OneBot 11 公开 API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)。具体 SnowLuma 版本是否实现转码与落盘路径需要在实际部署中验收，不能用模拟测试代替。

B站取得可下载的单段媒体流后，在原下载中一并提取音轨；不重复下载同一流。没有音轨、只有字幕、取流失败或单独音频流未支持时如实说明。听觉开关不会改变原有点赞评论权限或网络代理配置。

## 进度、预算与清理

- 文件最多64 MiB、音轨最多30分钟。FFmpeg 转为单声道16 kHz、32 kbps MP3，约30秒一段。
- 每轮最多5段，听觉模型阶段总计300秒；模型可在信息足够时提前停止。结果注明实际听过的范围，不代表整段已听完。
- 只在完整、合规的模型结果返回后提交片段进度；中途失败保留成功部分，继续时从失败处重试。模型或同步路由变化时旧结果不发布。
- 原始临时文件与落盘分段离开解码步骤即删除；用于续听的编码片段只在内存中保存，和画面合用容量受限、最多1小时的缓存，重启失效。缓存过期不删除已经写入的聊天文字记忆。
- 音频没有授权执行其中的命令。声音描述不等于准确逐字稿、身份鉴定或全片逐帧观看；不确定的内容应明确说明。

本次本地已验证真实 FFmpeg 音轨提取、SDK 参数可用性以及模拟接口下的权限、续听和失败处理。没有用真实模型服务或 QQ 账号进行音频上线验收。

## 自动听完整段音轨

- `听完音频`、`听完视频`、`自动听完`、`听完`：群里点名机器人；私聊直接发送，支持繁体。
- 可先发媒体再下指令；也可先下指令，在10分钟内上传音频/视频（群文件也支持预约）。
- `听完进度` 查询；`停止听完` / `暂停听完` / `取消听完` 停止本人在本聊天的任务或预约。
- 从当前缓存已成功的片段接续，自动每轮最多5段、每轮模型阶段300秒，不再因模型need_more=false而提前结束。
- 最多30分钟/64MB，每段约30秒；会产生多次听觉模型调用。全部处理后交给主模型，以当前人格统一回复。
- 任务不阻塞普通对话；完整收听最多同时登记4项，媒体模型批次仍按原锁串行，批次间让出。
- 超时、接口拒绝、缓存过期或模型设置变化立即暂停；失败段不记为已听。已有成功笔记保留，缓存有效期内重发“听完”继续。
- 同一聊天、同一发送人发来新媒体时，停止该人的旧任务。其他聊天及其他人的操作不能取消或接续本任务。
- 视频只自动听完整段**音轨**；不扩大画面采样，不声称全片画面都看过。
- 已在当前聊天缓存的B站音轨也能接续；本指令本身不负责新B站链接取流或绕过下载失败。
- 缓存仍从提取时起最多1小时、内存限额32MiB；临时文件提取后删除。任务与原始分段不跨重启恢复，聊天文字记忆不删除。
- 没有音轨、不支持音频的模型或中转仍明确失败。全部片段提交成功不保证逐字识别准确。

## 完整听力全局模式

管理员可发 `完整听力 开启` / `完整听力 关闭`，任何人可查 `完整听力 状态`。
别名 `全面听力`，支持繁体。默认关闭，开关原子写入full_hearing_mode.json，重启保留，不写config或密钥。
开启后，已触发的普通看视频、读音频会自动接着听全部提取片段，不再因need_more=false提前停；视频保留原有画面采样，并综合实际声音结果。
QQ路径复用可取消的完整收听任务；B站在取得实际音轨时按同样的分轮上限处理，包括已开启的主动浏览。
不会自动读取未点名群附件、绕过群白名单、启用B站或修改点赞评论权限；没有取得音轨就不能声称已听。
`听完进度`和`停止听完`仍按本人当前聊天生效。B站在途请求只能在返回后检查停止信号，不取消常驻B站runner。
关闭模式停止自动续听，恢复普通分轮行为；显式“听完”任务仍可使用。新的听觉路由会重新处理，不混合旧路由结果。
仍限每份30分钟/64MiB，每轮最多5段/300秒，缓存最多1小时。一次失败就暂停并保留成功进度，不能保证网络故障时仍听完。
此开关不替代听觉模型选择；请先填Key并选择支持input_audio的模型，当前主模型和视觉同步均不因它变化。
