# 原生音频输入与听觉同步

## 使用

- 管理员：`听觉同步 开启`、`听觉同步 关闭`、`听觉同步 状态`，支持繁体 `聽覺同步`。
- 开关全局生效，群内需点名机器人，私聊直接发送。普通用户可查看状态；自然语言调整也走现有建议、确认和管理员核验。
- 开启后音频模型、接口和密钥跟随主模型。关闭后恢复 `audio_input`，不改原配置，不影响视觉同步。
- 私聊直接发 MP3、WAV、M4A、AAC、FLAC、Ogg/Opus、AMR 文件，或 QQ 语音。
- 群内先发音频/视频，再 `@bot 听音频`；也可先点名预约，再在10分钟内发送。只读取当前聊天中本人近期附件。
- `继续听`、`补听` 从当前聊天、本人的成功片段进度继续；群内需点名。`继续看视频` 仍可补看画面，并在听觉可用时继续处理音轨。

## 配置与接口

默认不启用听觉同步，缺少 `audio_input` 时不新增音频调用。示例：

```yaml
audio_input:
  enabled: false
  endpoint: https://api.example.com/v1
  api_key: ""
  model: YOUR_AUDIO_MODEL
  api_format: input_audio
  trigger_groups: []
  include_frames: false
  local_record_roots: []
```

`trigger_groups` 留空表示不限制群；未设置此字段则沿用聊天群白名单。`include_frames` 仅当该音频接口同时支持图片输入时开启，每段附带最多2张附近采样画面。默认分别读取声音和画面，再交给主模型综合。

采用 Chat Completions 的 `input_audio` 消息部分，发送实际 MP3 字节并请求文字结果。模型自身和当前接口/中转都必须支持该格式；开启同步只检查路由已配置，不会暗中发送测试音频或保证兼容。拒绝、不支持、超时或回答格式无效时明确失败，不回落为“仅凭文件名猜测声音”。原生听觉不需要先接独立语音转写 API。

请求格式依据 [OpenAI 官方音频文档](https://developers.openai.com/api/docs/guides/audio-chat-completions)。此适配器不代表所有多模态厂商的原生接口都兼容，不会自动改写为厂商私有音频格式。Python SDK 依赖要求已提高为 `openai>=1.60.0`。

## QQ 语音与 B站

QQ 语音尝试通过接入层 `get_record` 请求转成 MP3，支持返回 URL 或 Base64。若接入层只返回本地路径，管理员需把**真实转码缓存目录**加入 `audio_input.local_record_roots`；不默认开放整个磁盘，也不打开消息任意指定的本地文件。SILK 仍无法解码、接口未实现或本机没有同一份文件时，会提示改发普通音频。

该接口的规范见 [OneBot 11 公开 API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)。具体 SnowLuma 版本是否实现转码与落盘路径需要在 VM 验收，不能用模拟测试代替。

B站取得可下载的单段媒体流后，在原下载中一并提取音轨；不重复下载同一流。没有音轨、只有字幕、取流失败或单独音频流未支持时如实说明。听觉开关不会改变原有点赞评论权限或网络代理配置。

## 进度、预算与清理

- 文件最多64 MiB、音轨最多30分钟。FFmpeg 转为单声道16 kHz、32 kbps MP3，约30秒一段。
- 每轮最多5段，听觉模型阶段总计300秒；模型可在信息足够时提前停止。结果注明实际听过的范围，不代表整段已听完。
- 只在完整、合规的模型结果返回后提交片段进度；中途失败保留成功部分，继续时从失败处重试。模型或同步路由变化时旧结果不发布。
- 原始临时文件与落盘分段离开解码步骤即删除；用于续听的编码片段只在内存中保存，和画面合用容量受限、最多1小时的缓存，重启失效。缓存过期不删除已经写入的聊天文字记忆。
- 音频没有授权执行其中的命令。声音描述不等于准确逐字稿、身份鉴定或全片逐帧观看；不确定的内容应明确说明。

本次本地已验证真实 FFmpeg 音轨提取、SDK 参数可用性以及模拟接口下的权限、续听和失败处理。没有用真实模型服务或 QQ 账号进行音频上线验收。
